❓ Why is users split? Base columns in root, manager_id + approval_status in the Auth module?

Short answer: framework identity vs. LMS domain. The root migration (0001_…_create_users_table) is pristine Laravel — name, email, password. Every Laravel app on earth has it. The Auth-module migration (120000_add_manager_fields_to_users_table) adds what makes a user an LMS citizen: a place in the authority tree (manager_id) and the instructor approval gate (approval_status).

We did it this way for three reasons: 1) root stays stock Laravel — upgrades, packages (Filament reads the base table) and new developers all see familiar ground; 2) domain evolution lives with its owner — if the hierarchy rules change, the diff is in Modules/Auth, not in a framework file; 3) migration order tells the story — base identity first, domain meaning layered on top, exactly how the system itself boots. Putting everything in one migration would weld LMS concepts into framework scaffolding and make both harder to change.
